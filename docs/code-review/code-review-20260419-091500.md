## 潜在问题和建议

### 1. 路径一致性风险

**风险**: 单例在插件初始化时使用 `directory` 参数创建，但工具调用时传入的 `args.projectPath` 可能与 `directory` 不同。

**建议**: 
- 验证 `args.projectPath` 与 `knowledgeBase` 的路径是否一致
- 如果不一致，考虑返回错误或使用正确的路径

**影响**: 中等 - 可能导致跨项目查询错误

### 2. 热重载行为

**风险**: 在开发模式下，插件可能被多次调用，单例可能会保持旧状态。

**建议**:
- 考虑在插件卸载或重新加载时重置单例
- 或者添加版本/时间戳检查

**影响**: 低 - 仅在开发环境可能出现

### 3. memory-lint-kb 的重复初始化

**观察**: lint 工具调用 `knowledgeBase.initialize()` 可能会重新加载整个知识库。

**建议**:
- 考虑添加标志避免不必要的重新初始化
- 或者提供轻量级的验证方法

**影响**: 低 - 仅影响性能，不影响正确性

### 4. 错误处理改进

**建议**: 当前的错误处理使用 JSON 字符串返回，可以考虑使用更结构化的错误响应。

**示例**:
```typescript
if (!knowledgeBase) {
  throw new Error("Knowledge base not initialized. Please run memory-init-kb first.")
}
```

**影响**: 低 - 当前实现已可用
